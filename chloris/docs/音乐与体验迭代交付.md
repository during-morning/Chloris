# Chloris 音乐与体验迭代交付

日期：2026-10-01。本文区分代码实现、自动化验证与真实平台验收，不将未运行的平台计入通过项。

## 本轮用户可见变化

- 默认 Absolutely 主题沿用暖纸、墨色和陶土色，图标统一走 Lucide 细线映射。保留 classic 与 terminal；终端主题主按钮使用白底黑字。
- 常用按钮有轻微按压反馈，封面切换和导航有过渡；系统启用减少动画时关闭过渡。导航动画只挂载一个路由容器，避免过渡期间复制 Navigator 的 GlobalKey。
- 手机书籍导出入口为「其他应用打开」，生成 TXT 后调用系统分享面板；电脑与 Web 为「保存到本地」。并行获取章节后按目录顺序导出，优先复用已保存正文，支持取消，空正文会明确报错。
- 缓存下载和书籍导出共用全局调度队列，沿用可配置并发数及单主机上限。任务重启恢复、多本书并行、快速取消再恢复、失败重试均保留已完成章节。用户取消的任务不会在重启后自动继续。缓存管理页提供继续／重试。
- 本地导入、用户下载的章节和音乐使用独立持久文件，不参与临时缓存淘汰。
- 书架及搜索过滤空标题、空身份和非法链接；保留合法单字书名及包含「登录」字样的书名。书架工具栏新增「检查无效书籍」：最多两本同时检查目录及首章，空目录／空正文与断网／超时分开显示。删除前列出具体书籍，独立下载保留。
- 音乐独立导航、搜索、发现、曲库、歌单、下载管理、地址解析、全局迷你播放器与完整播放器已接入。首页提供继续播放、最近播放与歌单入口；默认封面使用主题色绘制唱片。下载显示大小与速度，移动端导出音频和资源包使用系统分享。
- 音乐发现页沿用 Legado-E 的书源／书籍／章节组织方式，区分音频书源、显示来源计数，并把最近播放与曲库封面融入列表。完整播放器按 Legado-E 参考重做为沉浸式页面：封面铺成柔化背景，主封面加暖橙圆环，歌词透明居中并渐隐到底图上；空歌词保留导入入口；进度和播放区固定在底部。手机采用封面、歌词、控制区纵向布局，宽屏改为封面、歌词、队列并列。速度、音量、循环、随机、跳转、定时和队列仍可直接操作。参考：[Legado-E 项目](https://github.com/Luoyacheng/legado-E)。实际浏览器截图：`../build/music-evidence/music-full-player-mobile.png`、`../build/music-evidence/music-full-player.png`。
- 歌词支持普通文本、LRC、逐字 LRC、SRT、WebVTT、结构化 JSON、翻译、音译、导入、偏移与点击跳转；两倍文字大小下的三行双语歌词已补充回归。

## 音乐链路与持久化

- TrackRef 保存稳定身份和原始来源引用；播放及下一首预解析时才取得临时地址。
- AudioResolver 复用搜索／详情／目录／正文、Cookie、变量、JS 与请求准备。章节字符串数组为连续分段；通用数组要求选择；音质与多曲目保持独立语义。POST 请求体和请求头经媒体网关传递。
- MusicPlaybackCoordinator 唯一管理队列、解析代次、播放意图、驱动、定时停止、重复／随机、速度、音量、进度与歌词。切换页面保持播放，重启恢复时保持暂停。
- 数据库版本 9 增加音乐元数据、歌单及成员、歌词、历史、恢复状态与下载记录；7→9、8→9 迁移有自动化覆盖。既有 v9 连接也补建排序索引。
- 曲库查询分页并只读元数据；本地文件复制到应用持久目录，以内容指纹去重，不把大音频存进 MusicTrack.bytes。
- 下载管理器默认并发 2、单主机 1；普通文件支持 .part、Range 续传及资源校验；连续分段保存清单；HLS 点播保存播放列表、初始化段、分片与 AES-128 密钥并改写相对地址。直播及 DRM 不可离线下载。
- Web 使用 OPFS／IndexedDB 与 Service Worker，原生使用持久文件。本地 HLS 以资源包导出，保持原始编码。
- 动态解析按需启动并有会话取消、超时与释放。Web 服务使用 Playwright Chromium 的独立 BrowserContext；支持延迟 DOM、fetch／XHR、POST 资源候选及内联 HTML。
- 媒体网关使用不透明会话 ID，凭据不进入播放 URL；支持 Range／HEAD、POST 与 HLS 子资源。系统进度发布独立订阅位置，避免每次进度更新重建队列。

## 实际验证结果

最终测试计数、构建大小及校验值见 `../build/music-evidence/verification.json`；原始日志保存在同一目录。

已完成的验证：

- Flutter 整应用单元与组件测试：书籍、缓存、分页、数据库、音乐解析、播放器、歌词、下载、主题与窄宽布局。
- chloris_engine 共享引擎测试：HTTP、取消、规则、JS 及上游语义。
- 真实 Chromium：延迟 DOM、内联 HTML、POST 捕获、取消、超时、私网地址限制、连续 30 个解析上下文释放。
- 真实 Chromium 离线：OPFS 文件、Service Worker 的 206 Range／HEAD、HLS 相对资源路径、真实 WAV 播放／暂停／Seek、驱动反复加载与释放，以及音乐页导入 WAV、打开播放器、断网刷新后恢复队列并播放。
- 原生持久文件测试覆盖大于 8 MiB 的导入、内容去重、删除源文件后保留管理副本、分段与 HLS 文件布局。HLS 文件结构测试不等同于六个平台的实际 HLS 解码验收。
- 三种主题、240×280／320×180／390×844／1300×700 与 1×／2×文字缩放的播放器组件回归。
- 音乐播放器样式回归：播放器、歌词和导航测试共 16 项通过，覆盖三主题、四种窄宽屏和 1×／2×文字缩放；Release Chromium 的本地 WAV 导入、完整播放器、手机布局截图与离线重启测试通过。

### 性能实测与限制

一万首曲目、首屏 100 条元数据的 40 次查询微基准记录在 `library-query.json`。`EXPLAIN QUERY PLAN` 验证使用 `music_tracks_title_nocase` 索引。这是在 SQLite 内存库及 Flutter 测试进程中的查询，不包含磁盘冷启动、布局和绘制，不能据此声称完整曲库首屏达到 ≤300 ms。

已减少每章重复目录扫描、下载任务每章立即全量写入、普通封面重复加载、搜索每源完整列表复制、全音乐页面随位置通知重建等工作。此前分页控制器、缓存预算、worker 与 macOS JS helper 改造继续保留。

尚未完成同机同数据的 macOS Profile 前后对比、DevTools CPU／内存采样、帧耗时 P95 与 GC 后对象留存验证。帧超预算 <1%、长章节首页 ≤500 ms 等仍为验收目标。

## 构建和运行

Android Release 使用仓库现有 debug signing 配置，为可安装测试包，不是商店发行签名。

Web 使用标准 JavaScript 构建，`--no-web-resources-cdn` 将渲染器资源随包提供，`--no-wasm-dry-run` 跳过非交付目标的 Wasm 检查；当前依赖尚未满足 Wasm 编译条件。离线基础能力要求 HTTPS 或 localhost。动态网页解析需要运行随包附带的服务端 worker；本地音频和静态直链不依赖该 worker。

```sh
cd chloris
flutter test
flutter build apk --release
flutter build web --release --no-web-resources-cdn --no-wasm-dry-run
cd tool/browser_worker
npm ci
npx playwright install chromium
cd ../..
dart run tool/serve_web.dart 2328
```

服务默认仅监听回环地址。部署时按现有服务连接及身份校验配置；浏览器 worker 的依赖与版本由 package-lock.json 固定。macOS／iOS 必须先具备完整 Xcode；Windows／Linux 使用对应平台工具链。
